# 利確・損切 判定仕様書

---

# 1. 利確条件

前回高値（ショートなら前回底値）付近、または節目（キリのいい価格）で利確する。

## 前回高値・前回底値の定義

タッチ回数に関わらない、直近のスイングハイ/ロー1点（`analysis/swing_points.py`）を使う。
支持線・抵抗線（3回タッチで確定したライン）は使わない。直近すぎる押し目が3回タッチの
条件を満たさず候補に挙がらないケースがあるため。

## 節目（ラウンドナンバー）の刻み幅

株価水準に応じて刻み幅を変える。

| 株価水準 | 刻み幅 |
|----------|--------|
| 1,000円未満 | 100円 |
| 1,000円〜9,999円 | 500円 |
| 10,000円以上 | 1,000円 |

例: 3,000円の次の節目は3,500円。

## 採用ルール

前回高値（安値）と節目のうち、エントリー価格から**遠い方**を利確価格として採用する
（どちらか片方しか無ければそちらを採用）。

※ 当初は損切と同様に「近い方」としていたが、バックテストで前回高値が近すぎる
ケースが多発し、数日で小さく利確する一方、損切は10日以上かけて大きく損失が
出る非対称な結果になった（トヨタ7203のロング14件で平均リターン+0.71%、
リスクリワード比0.1〜0.5程度の浅い利確が多発）。数週間〜1ヶ月のスイング
トレードという想定に合わせ、利確側は目標に余裕を持たせる「遠い方」に変更した。

※ ショートのみ「近い方（狭め）」にする案も試したが、勝率は34.4%→44.8%に
改善したものの、平均勝ちが縮小（+4.50%→+2.44%）し平均リターンは悪化
（-0.47%→-1.26%）したため、ロングと同じ「遠い方」に戻した（market_filter_spec.md
とあわせて検証。ロング・ショートとも利確・損切のルールは同一に統一）。

---

# 2. 損切条件

前回底値（ショートなら前回高値）を割った時、または20日線を割った時に損切りする。

## 損切価格の確定方法

前回底値（安値側の直近スイングロー）と、エントリー時点の20日線のうち、
エントリー価格に**近い方（よりタイトな方）**を損切価格として採用する。

- エントリー時点でこの価格を確定し、以降は固定値として扱う（20日線が動いても
  日々再計算はしない）
- リスクリワード比の計算に使う「損切幅」を、エントリー時点で確定させるため

---

# 3. リスクリワード比

利確幅 ÷ 損切幅 を計算する。目安は2:1。

- **候補の絞り込みには使わない。** 参考情報として計算し、結果に含めるのみ
- 損切価格・利確価格のいずれかが無い場合、または損切幅が0以下の場合はNoneを返す

---

# 4. 実装

`rules/exit_rule.py`

- `get_previous_swing_high` / `get_previous_swing_low`
- `get_round_level_above` / `get_round_level_below`
- `get_take_profit_price` / `get_stop_loss_price`
- `calculate_risk_reward_ratio`

`rules/entry_rule.py` の `evaluate_entry` が、エントリー候補判定に成功した場合の
戻り値へ `stop_loss_price` / `take_profit_price` / `risk_reward_ratio` として含める。
